## 五、P0：先修复任务与积分生命周期

### 1. 预扣到期与执行期限分离

修复现有 15 分钟预扣自动清理与视频最长 30 分钟执行并存的问题。

- 孤立且已过期的预扣，可以在事务内确认没有关联任务后释放。
- 已绑定 queued、processing 或待核对任务的预扣，交由任务状态机处理。
- 不因预扣自身到期而直接解冻仍在执行的任务。
- 清理、建单关联、结算和退款竞争时，在锁内重新验证关联和状态。
- 任务成功后，即使原预扣时间已过，也应依据有效任务与预扣状态完成一次正确结算。
- 延长执行时间不应简单通过无限延长所有预扣 TTL 实现。

优先复用本地 `cleanupExpiredReservations`、`onlyIfUnlinked` 等相关修复，补齐竞态和调用方测试。

### 2. Provider 已受理与结果未知

统一表达以下执行阶段：未派发、明确未受理、已受理、受理情况未知、运行中、明确成功、明确失败/取消、结果归档失败、待核对。

可以沿用现有主状态并增加子状态和事件，保持已发布接口兼容，不要求直接替换数据库全部枚举。

- 已有 Provider receipt 时，只查询和恢复原任务，不再次调用 createTask。
- 上游受理后快速轮询异常，保留 receipt 并进入恢复流程。
- 请求发送后网络断开，无法确认受理情况时，保留不确定性并进入待核对。
- 等待时限到达只改变等待和处理策略，不能据此认定 Provider 未收费。
- 明确未受理或明确失败后，按既定规则释放积分。
- 迟到成功、重复回调和 Worker 重启后继续使用原任务关联。
- 原任务不确定时，不自动切换供应商创建第二笔可能收费的任务。

保留长期轮询已有的瞬态错误恢复机制，统一快速轮询和长期轮询的错误语义。

### 3. 幂等与并发

- 同一用户、同一幂等键，只能创建一个有效任务和一笔有效预扣。
- 同一键携带不同模型、参数或项目/节点上下文时返回明确冲突，不静默复用错误任务。
- 报价消费、预扣、任务创建、事件、Canvas 项目关联保持同一事务。
- 保留唯一索引、用户幂等锁、钱包行锁和事务内再次查重。
- 并发提交不能导致钱包负数或重复冻结。
- 重复成功、失败或取消事件只生效一次。
- 对外回调和内部重试均有稳定的幂等约束。

### 4. 成功、归档失败与结算失败

- Provider 成功与用户已获得结果分别记录。
- 成功终态、素材入库、消费确认、成本记录和事件保持事务一致。
- 外部生成已成功但本地事务失败时，恢复本地完成步骤，避免重新生成。
- 归档失败保留 Provider 成功证据及成本责任，优先恢复归档。
- 按既定赔付政策退款时，用户退款与平台供应商成本分开记录。
- 同一 attempt 的成本写入不得因重试或多个错误分支重复累计。

### 5. 分桶与到期权益

保留每日免费 → 订阅 → 永久积分的扣减顺序。

退款按原预扣分桶处理，明确每日积分已过期、订阅周期已变化时的规则；不得无提示复活已过期权益或转为永久积分。

展示和比较余额时使用有效余额，原始过期桶数值用于解释历史。TASK_RESERVE 已扣除可用余额，TASK_COMMIT 为消费确认时 delta 为 0 的语义保留，避免成功后再扣一次。

## 六、P1：统一模型目录与能力契约

### 1. 逻辑模型与实际线路

保留稳定逻辑模型 ID，供应商模型、版本、端点和参数映射作为其线路配置。用户选择逻辑模型和能力，服务端决定符合条件的实际线路。

每个逻辑模型统一维护：名称、品牌、类别、描述、封面、排序、版本、能力、默认参数、价格、发布状态、用户和站点范围。

同一模型的不同供应商映射独立维护：真实模型 ID、端点、适用任务、分辨率、时长、输入输出限制、地区、授权条件、成本、并发及版本。

禁止通过相似名称推断两个线路能力等价。保留旧模型 ID 与历史账单关联，合并目录时提供可追溯映射。

### 2. 能力分类

| 一级能力 | 应支持描述的操作 | 核心参数与资源角色 |
|---|---|---|
| image | 文生图、图生图、局部重绘、多参考图、放大 | 提示词、参考图、蒙版、尺寸、比例、数量、质量 |
| video | 文生视频、图生视频、首尾帧、视频编辑、延长 | 首帧、尾帧、参考视频、时长、分辨率、音轨 |
| audio | 语音合成、识别、音色转换、音频处理 | 文本、音频、语言、音色、授权、字符/token/秒 |
| music | 文生音乐、延长、编辑、伴奏 | 歌词、风格、参考音频、时长、输出数量 |
| text | 对话、推理、工具调用 | 消息、上下文、输入/输出 token、工具权限 |
| agent | 组合工作流、多步骤任务 | 目标、上下文、工具、子任务、预算 |

模型只开放已实现的实际能力。契约应能覆盖表中操作；本期没有对应线路和适配器的操作明确禁用，并标出后续实现范围，不伪造支持。

### 3. 版本化契约

V4 是开发方案版本，已有接口继续以 Schema V2 演进，避免无意义更名。

目录顶层包含 schemaVersion、catalogVersion；每个模型提供：

- logicalModelId / 稳定模型 ID。
- capabilityVersion、能力分类与 taskType。
- inputSchema、outputSchema、约束、默认值和支持的规格。
- 输入资源角色、数量与大小约束。
- 计费单位和输出数量规则。
- 可用状态、不可用原因、验证等级及发布时间。

服务端与客户端使用同一已发布能力契约。前端按契约渲染，服务端独立校验，不能只依赖浏览器校验。

旧客户端无版本请求提供明确的兼容响应；新客户端请求不支持的版本时返回稳定错误。缺失 capabilityVersion 的旧响应不得被新客户端当作完整 V2 能力。

### 4. 报价与任务绑定

报价和创建任务绑定同一模型、能力版本、taskType、规范化参数、输出数量、素材 ID、权益和计费规格。

参数或素材变化、能力版本失效、价格不再适用时，预扣前拒绝或要求重新报价。报价不能只携带一个总积分数，任务也不能在执行时悄悄换规格。

保留现有参数摘要、报价有效期、用户归属、映射版本、价格版本与候选线路快照。

### 5. 音乐分类迁移

将 music 从旧 audio 归并中独立出来，覆盖目录、挂载、默认模型、选择器、任务和定价。

先扩展读写契约，再迁移现有音乐模型与挂载，保留旧配置兼容；随后收敛旧写入。不得因改枚举丢失已有音乐模型、任务或历史账单。

### 6. 统一可用性

用共享业务服务计算“能否展示、能否报价、能否执行”，各场景保留合理差异，但共用规则来源和原因码。

检查模型发布、用户权限、站点分配、能力规格、启用线路、审核、端点、凭据、成本、健康、配额和并发。

模型已挂载但没有可用线路时，显示可理解的原因。不能把 `enabled`、`approved`、健康标签或验收通配配置当作全部条件通过。

## 七、P2：供应商凭据与统一调度

### 1. 凭据管理

所有平台供应商凭据只在服务端读取，浏览器不能指定实际 API Key 或覆盖 Provider 配置。

复用加密数据库和现有环境变量读取。后台明确展示实际来源：环境配置、加密数据库、未配置、解密错误。保持现有优先级，任何改变都需有明确迁移与兼容处理。

后台至少展示：

- 当前有效来源、环境和最近变更时间。
- 配置存在状态、解密结果和实际执行是否已使用新配置。
- 认证验证、模型权限、生成验证分别对应的状态和时间。
- 余额/配额的来源、币种、观测时间及是否未知。
- 环境配置覆盖数据库配置时的明确提示。

密钥保存、轮换、撤销后处理适配器实例缓存，确保界面状态与真实执行一致。错误日志不得输出密钥、Token、Cookie、完整签名 URL 或敏感响应。

### 2. 健康与能力验证

将“凭据已配置”“接口连通”“鉴权成功”“具备模型权限”“真实生成通过”分开。

现有仅检查密钥非空的探针返回配置级状态，不提升为鉴权或生成验证。未知余额显示未知，不能用数据库默认 0 冒充实际余额。

健康状态有来源、时间和适用范围。路由读取同一套规则，并能解释过期、熔断、限流、余额或权限导致的拒绝。

### 3. 调度策略

保留并完善成本优先、质量优先、稳定优先、均衡及管理员优先级的业务语义。对存量 priority 配置给出确定实现和兼容方案，避免默默按其他策略执行。

调度顺序：先做硬性准入，再对合格线路排序。不得因某条线路便宜而绕过能力、凭据、权限、成本或健康约束。

选择记录包括：策略版本、合格候选、排除理由、实际 Provider/模型/端点、映射和价格版本、成本/汇率快照、预算上限、receipt、重试和终态。

### 4. 故障转移

同一报价仅在能力等价且成本上限内切换线路。

- 参数或内容被明确拒绝时，不以切 Provider 绕过规则。
- 已受理或受理未知任务按 P0 恢复，不盲目切换。
- 跨逻辑模型备用需要明确的等价约束和用户行为规则。
- Canvas 不自行选择供应商，不自动改用浏览器 Key。
- 不把历史文档中的固定主通道策略强行覆盖现有业务配置。

### 5. 成本与价格

成本以实际 Provider 模型、任务类型和规格维护版本，支持不同币种及计费单位。区分公开价、账户实际价、人工确认价和保守上界；有来源与有效期。

支持请求、图片、输入/输出秒数、token、字符、规格和组合计费。某模型没有适用成本时，应明确阻止可靠报价或使用经过批准且有期限的上界规则，禁止缺成本默认免费。

报价由服务端统一计算，两站使用同一用户和参数时得到同一规则结果。保留当前售价/积分换算、准备金、毛利底线、舍入和最低收费的明确政策，开发过程中不得自行改变商业数值。

分别定义并统一实现：积分售卖面值、定价换算、财务估值、供应商成本汇率、套餐赠送与价格策略版本。处理 ¥0.07/积分、现有后台估值和动态汇率的口径差异，让界面和计算有一致解释。

价格更新只影响适用的新报价；历史任务继续使用其报价、权益和汇率快照。固定价、公式价、人工覆盖和到期时间均要有确定优先级与原因。

### 6. 成本记录与对账功能

实现任务、attempt、Provider receipt、成本记录与对账事项的可追踪关联。

- estimated、provider_reported、reconciled 独立保存。
- 实际成本未知保留 null，不用估算值或 0 代替。
- 对账支持录入/关联账单证据、差异原因及处理状态。
- 历史成本缺失保留缺口和原因，不修改用户积分来凑平。
- 成本重复写入通过幂等约束和调用路径收敛解决。
- 平台赔付和用户退款独立于供应商成本核销。

先把产品功能和数据约束实现，再按授权处理真实历史账单；不把等待外部账单作为停止本地开发的理由。

## 八、P3：完成 Canvas 全模态平台接入

重点文件包括 `web/src/services/api/koyosim.ts`、图像/视频/音频/文本相关 API、模型能力工具、配置 Store、画布页面与节点组件。已有集成先沿用，补齐服务端契约差异和缺失交互。

### 1. 模型选择与参数

- 读取主站正式发布且对当前用户可用的模型。
- 按 image/video/text/audio/music 分类展示。
- 根据能力动态展示尺寸、比例、时长、质量、数量、参考素材等参数。
- 模型切换时校验已有参数，不静默丢弃或带入不支持的值。
- 不可用模型给出原因和明确的手动选择入口。
- 默认模型必须属于当前用户可用挂载。
- 同一参数对象用于展示确认、报价和创建任务，避免字段映射漂移。

### 2. 各模态交付

图像：完成文生图、已发布图生图/编辑及多输出与素材引用；蒙版、多参考图等操作按具体模型能力开放。

视频：完成文生视频、图生视频及已发布首尾帧/参考视频能力；时长、分辨率、音轨等与报价和真实线路一致。

文本：接入主站平台文本任务，正确保存文本结果；流式与非流式按现有服务能力处理，中断等待和任务取消语义明确。

语音：明确文本、音色、语言、格式、速度及授权条件；区分普通 TTS 与需要特殊资源的克隆/转换模型。

音乐：独立选择与参数入口，支持现有已发布任务，正确展示音频结果和多产物。

不要只增加一个模态菜单就算完成；每个本期开放能力都必须连接真实平台接口、任务状态、结果类型和计费规则。

### 3. 生成与恢复体验

- 先验证输入，再获取服务端报价，再创建任务。
- 保留用户明确提交行为，重试前说明是否复用原任务。
- 每个独立批量任务有唯一幂等键；恢复和网络重试沿用原键。
- 任务创建后刷新只恢复，不再次 POST 同一生成请求。
- 中断当前页面等待与取消服务端任务分别呈现。
- 已受理、处理中、待核对、明确失败、归档失败有对应展示。
- 结果与原项目、节点、用户和任务保持关联。
- 多结果按实际返回与计费契约展示，不遗漏已交付产物。

### 4. 平台与 BYOK

平台调用只使用服务端凭据和平台积分。BYOK 由用户明确选择，费用由其选定渠道承担。

平台模型失败、未登录、能力不可用或会话变化时，保留输入并提示处理，不自动变成 BYOK 请求，不自动更换模型。

## 九、P4：统一用户资料、会员、积分与历史

### 1. 主站账户为权威

| 功能 | 主站职责 | Canvas 行为 |
|---|---|---|
| 登录/退出/注册 | 认证和 Session | 使用共享身份，提供清晰入口 |
| 头像/昵称/邮箱 | 权威读写与验证 | 同步展示或调用授权接口 |
| 密码/社交账号绑定 | 安全管理与验证 | 引导到主站对应页面 |
| 个人资料 | 完整管理 | 复用主站数据，保留编辑器偏好 |
| 积分 | 权威钱包与账本 | 展示有效余额、冻结、消费及退款 |
| 套餐/会员 | 购买、履约、到期和权限 | 读取同一权益，入口进入主站 |
| 充值/支付 | 创建订单、入账与对账 | 进入主站，不创建独立充值系统 |
| 生成历史 | 统一任务与素材归属 | 按 Canvas/项目筛选和恢复 |
| 画布项目 | 主站云端项目 API | 编辑、版本冲突处理和本地交互 |

### 2. 身份和缓存

保留 Cookie、Origin、写请求标识、用户归属和 expectedOwnerUserId 校验。账户切换后清理相应缓存和订阅，不把旧用户项目或素材展示给新用户。

登录失效保留未提交输入与画布编辑状态；重新登录后重新确认用户和项目归属，再执行收费操作。

### 3. 积分与权益展示

统一使用有效余额和主站权益，不在 Canvas 按本地规则推算另一份余额。

消费记录能关联任务、模型、站点、金额和状态。冻结不是第二次消费，退款不等于供应商成本为零。会员功能在前后端均执行权限校验。

### 4. 素材与结果

平台素材输入优先使用 asset ID，服务端校验用户、类型、状态和用途后解析。短期签名 URL 不作为永久任务标识。

生成结果归档到私有存储并保存 object key、asset ID、类型、规格、状态和来源。下载、预览和重试有明确授权路径。

主站素材库与 Canvas 素材选择器共用用户归属和状态；项目引用、删除/回收站及历史任务结果的影响清楚可见。统一处理遗留静态上传路径，避免绕过服务端授权。

Canvas 项目任务展示以 creations 权威状态为准，不因关联表缓存仍为 queued 就重复执行。

## 十、P5：实现主站统一模型运营中心

沿用现有后台页面和服务逐步整合，形成完整操作流程。遵循现有 UI_DESIGN_SYSTEM、UI_REPAIR_INSTRUCTION、品牌、主题、组件及权限规范。

### 1. 后台模块

| 模块 | 必须可完成的操作 |
|---|---|
| 运营总览 | 查看发布模型、任务、收入估算/已确认成本、失败和待处理事项 |
| 模型目录 | 新增/编辑逻辑模型、品牌、分类、显示、排序与发布状态 |
| 能力管理 | 管理 taskType、输入输出、参数、规格、版本及默认值 |
| 供应商中心 | 管理端点和加密凭据、来源、环境、验证等级、余额/配额 |
| 线路调度 | 管理模型映射、策略、优先级、预算、并发、熔断及备用 |
| 模型定价 | 维护成本版本、计费 SKU、积分售价、毛利、覆盖与有效期 |
| 用户与站点分配 | 配置免费/会员/企业、用户范围、主站/Canvas 挂载及默认模型 |
| 任务中心 | 查看状态、receipt、attempt、错误原因、恢复和待核对事项 |
| 财务中心 | 查看钱包、冻结、消费、退款、成本和对账关联 |
| 发布记录 | 查看配置变更、版本、操作者、原因及可恢复的旧配置 |

### 2. 模型接入与发布流程

实现以下可操作流程：

供应商配置 → 凭据来源与验证 → 导入/新增模型 → 建立真实映射 → 配置能力与规格 → 确认成本 → 设置积分售价和路由 → 分配用户及站点 → 完成指定验证 → 发布。

已有 Provider 适配器支持的新模型，应通过配置完成接入；新的 Provider 协议仍允许增加服务端适配器，但不要求给同类模型逐个添加前端硬编码。

### 3. 发布前检查与说明

页面汇总实际阻断原因并提供处理入口，例如：端点缺失、没有适用价格、凭据由环境覆盖、仅完成配置验证、模型权限未知、规格未声明、用户不具备权益、未挂载 Canvas、协议版本不支持。

分别展示可展示、可报价、可执行、已验证状态。保存草稿和停用不应被无关字段阻塞；正式发布必须满足对应能力的要求。

### 4. 价格和权限变更

保存价格/线路/能力时创建可追溯版本。更新后让相关缓存按既有机制失效，并明确旧报价、执行中任务和历史账单继续使用什么规则。

停用只阻止新的适用任务；已受理任务继续恢复和结算。模型 ID、历史 receipt、积分记录及素材引用不得被级联破坏。

## 十一、数据结构与兼容实现

优先扩展现有表：ai_models、provider_models、provider_model_price_versions、model_pricing、model_site_price_versions、generation_quotes、creations、generation_attempts、provider_cost_records、credit_wallets、credit_reservations、credit_ledger_v2、canvas_projects、canvas_project_jobs、user_assets。

新增字段和索引要对应明确业务约束；已有等价结构先复用。迁移按先扩展、回填、切换读写、最后收敛推进，保证旧生产客户端和执行中的任务可继续工作。

核心数据要求：

- 逻辑模型、能力、映射、价格和策略版本可关联。
- 报价、预扣、任务、attempt、成本、素材和项目引用可追踪。
- 幂等约束覆盖任务、报价、账本和必要的成本写入。
- owner 校验不能只依赖客户端传来的 userId。
- 未知成本和未知执行状态有明确表达，避免伪造默认值。
- 迁移脚本可在隔离数据库重复验证，正式执行前有备份与回滚步骤。

## 十二、必须完成的测试

为高风险业务使用真实 PostgreSQL 事务与锁、假 Provider、可控时间和隔离存储。对接口与前端做针对性测试，运行相关类型检查和构建。修复失败后只重跑受影响检查，避免无意义反复全量运行。

### 1. 财务与任务

- 同幂等键并发、同键不同参数、不同任务争用余额。
- 报价过期、归属错误、参数变化和重复消费。
- 第16分钟仍执行、第25分钟成功的视频任务不被提前解冻。
- 清理预扣与任务关联/结算竞争。
- Provider 已受理后断线、快轮询异常、无 receipt 的发送结果未知。
- Worker 重启、迟到回调、重复回调和原任务恢复。
- Provider 明确失败释放一次，成功确认一次。
- 归档失败、终态事务失败、重复成本写入及后续恢复。
- 每日/订阅桶过期、周期变化后的退款和有效余额计算。

### 2. 模型、路由与定价

- 旧/新 Schema 客户端兼容、未知版本、能力版本变化。
- 所有开放规格在选择器、报价和执行之间一致。
- 无端点、无适用成本、过期健康、配额不足及无模型权限。
- 环境覆盖 DB 凭据、解密失败和轮换后的实例缓存。
- 四类调度及存量 priority 语义。
- 故障转移遵守报价候选、等价能力和成本上限。
- 两站相同输入使用一致规则，历史价格和汇率不被重算。

### 3. 双站与 Canvas

- 主站登录进入 Canvas，同一用户、资料、会员和有效余额。
- 切账号、过期登录、缓存清理、跨用户项目与素材拒绝。
- 每种本期开放模态的参数、报价、任务、结果展示与历史恢复。
- 平台失败不调用 BYOK，不自动更换模型。
- 批量任务、刷新恢复、停止等待和服务端取消语义。
- 项目版本冲突、多标签页及结果回填到原节点。
- 私有素材预览/下载、失效签名、归档恢复和遗留静态路径权限。

### 4. 管理后台

- 新增同类模型无需改前端代码。
- 草稿、发布、停用、重新启用及版本恢复。
- 用户/套餐/站点分配即时反映到目录和执行权限。
- 保存价格后新报价生效，旧任务保留其快照。
- 不可用原因真实且可操作，健康验证等级没有被夸大。

### 5. 真实生成

只有拿到本次明确的模型、能力、次数及金额/积分预算后才执行。没有预算时完成上述隔离测试，列明待进行的真实验收项，不提交生产收费任务。

真实验收需关联 quote、唯一 job、Provider receipt、终态、私有素材和下载、积分结算/释放及成本状态。调用失败后不自行扩展测试数量或切换其他收费模型。

## 十三、开发过程与交付要求

每完成一个优先级内的完整批次：

1. 给出已实现行为及涉及文件。
2. 说明复用了哪些已有实现，实际补齐了什么。
3. 运行该批必要测试与构建，报告真实结果。
4. 说明兼容、迁移、剩余问题和发布影响。
5. 按仓库规则提交明确范围的改动，不包含其他人的工作。
6. 连续推进下一批，不每完成一个小步骤都等待重复确认。

需要用户决定的商业规则或边界值，集中说明具体影响；已有会话授权和规则能够确定的事项直接执行。

进度更新以完成的功能、测试结果、重要失败和需要用户处理的阻碍为主。不能把“完成检查”“写好计划”当作代码交付。

Canvas 功能变更同步更新其 todo、pending-test 和必要的 CHANGELOG；主站开发说明保持简洁，只记录实际接口、数据和使用方式。不要制造多份重复的事实文档。

## 十四、发布候选与回滚

本地开发完成后，准备明确提交对应的构建产物、迁移、环境变量名称说明、兼容验证和回滚步骤。

涉及生产时按会话授权执行，保留当前源码增量、配置、数据库备份及持久化数据。确认两个 Next 进程与 Worker 使用一致的发布版本，服务端兼容完成后再发布 Canvas 新客户端。

避免覆盖运行中的构建目录；使用项目现有的受控发布方式，并验证制品清单和实际引用资源。回滚应用不能删除真实已发生的积分结算，数据库采用兼容迁移和明确的数据修复步骤。

发布验证覆盖主站、Canvas、Worker、数据库连接、已创建任务恢复和素材权限。未经预算批准不以真实付费生成作为自动发布步骤。

## 十五、最终完成标准

满足以下条件，才认定约定开发范围完成：

- 两站共用同一身份、资料、会员、钱包和消费记录。
- 模型目录、能力、参数、用户权限和站点挂载来自同一服务端规则。
- 报价、预扣、任务、执行、素材和结算形成一致可恢复链路。
- 已受理或结果未知任务不会被重复创建或因等待期限盲目退款。
- 所有本期开放模态正确接入平台任务，BYOK 选择明确。
- 实际供应商、成本版本、价格政策和路由原因可追踪。
- 后台能够完成供应商、模型、能力、线路、售价、分配和发布操作。
- 相关事务、并发、故障、接口、前端和兼容测试通过。
- 已实现、已测试、已部署、真实生成已验收的状态分别清楚标注。
- 尚需生产授权、外部账单或付费预算的事项明确列出，其余已授权开发工作完成。

现在从 P0 开始：阅读相关现有修改，完成预扣到期与任务恢复的代码和测试，再按优先级持续推进。
