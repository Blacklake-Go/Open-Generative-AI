## 执行阶段

### 1. 重新建立现状基线

只读检查线上 Canvas 页面、正确 API 源、`/api/live`、`/api/ready`、匿名认证门禁和 CORS；核对生产 HEAD/工作树漂移、运行 BUILD_ID、运行 manifest 中客户端依赖的全部 Canvas 路由、构建来源、发布入口和回滚方式。识别 Canvas 客户端实际请求的 API，确认 `/api/*` 返回的确是 API JSON 而非 SPA fallback HTML。生产信息有变化时，以本轮证据为准。

重新追踪完整链路：当前登录身份 → 服务端模型/能力与报价 → 项目及 generation job 事务 → 幂等键 → 积分 reserve/commit/void/refund → Worker/Provider 终态 → 对象存储 Asset → 项目节点/历史/下载。标记每一步的代码位置、真实运行证据和缺口。

### 2. 先完成图片 P0，不扩大未验收能力

核对图片文生图、图生图、节点后继、重试和普通创作输入，统一使用 KoyoSIM 服务端 quote/job/poll/Asset 链路。线上 Server Mode 禁止调用浏览器端 Provider、用户自带 Key、任意 Provider URL 或本地 Agent 作为生成兜底。模型必须同时通过画布挂载、当前路由资格及真实端到端验收白名单；缺模型时明确报不可用，不得自动挑第一个模型。报价、余额、参数和报价过期状态来自服务端；价格改变需重新确认；超时先查询原任务，不能盲目重建任务。

逐项审计 Server Mode 的所有路由和底层服务入口，尤其 `/image`、`/video`、`/config` 等独立工作台，以及 `requestGeneration`、`requestEdit`、图像问答、视频任务创建/轮询、音频生成和插件/脚本回调。只隐藏按钮或把路由重定向不够：底层入口也必须在任何 Provider 网络请求之前 fail closed；本地模式的既有能力要保持不变，并分别测试。

对蒙版、角度、多角度、超分、反推提示词、扩图、全景、三视图、智能打光、插件生成等动作逐项核对真实模型、参数、成本与终态。没有专项 E2E 证据时，从工具栏、菜单、模型能力配置中隐藏或禁用，并在底层生成、重试、插件回调等入口拦截。纯本地裁剪、切图、缩放等操作要清楚标为本地处理，不冒充云端 AI 生成。

### 3. 项目、账户和素材隔离

项目保存/版本冲突、云素材上传、结果节点和来源连线、全局历史、刷新/跨设备恢复与 owner-scoped 下载都必须使用当前 KoyoSIM 账号。Server Mode 的云项目缓存只允许在会话已确认且 owner ID 匹配时展示或操作；匿名、加载中、错误、owner 缺失、切换账号及迟到的异步响应全部 fail closed。覆盖列表、自动打开、直达/深链、选择、导出、删除、恢复、自动保存；登出立即清除私有会话及私有展示。写请求携带发起时 user ID 只能用于竞态校验，服务端仍须按认证 Cookie 得到的身份校验 owner，并在写 DB/对象存储/创建 quote/job 之前拒绝身份不匹配请求。

所有 `koyo-asset:<id>` 参考素材必须在 Provider 执行前按任务 owner 查找；仅规范对象键可转换为 owner-scoped HTTPS 签名 URL。外部 URL、绝对路径、反斜杠、目录穿越、删除素材和越权素材都要 fail closed。检查任务成功后 Asset 同步的幂等、并发、重试和有限终态：无有效对象键或 owner 下载信息时，不得返回可下载成功；同步超时要明确终态，不能无限 loading 或假成功。

### 4. 积分和财务一致性

检查预留凭单金额、钱包冻结额、分桶拆分、账本流水和幂等状态。冻结余额不足、钱包缺失或记录不一致时必须停止结算/释放并提示对账，不能用 `Math.max(0, ...)` 掩盖差额。失败/取消必须幂等释放原预扣金额，成功只能按已核实成本提交；未知 Provider 成本保留待核对状态，不得填 0。

每日与订阅积分会过期。核对任务跨过期点时的原桶释放、过期时间、账本与用户可见余额是否一致。没有明确业务规则时不得擅自延长有效期、转成永久积分或静默吞掉返还；把问题标记为 `Unknown`，给出需确认的规则和受影响路径后继续其它工作。

### 5. 严格测试和状态分级

先跑相关静态检查、单元测试与必要的隔离数据库测试，覆盖 owner/双账户、幂等、事务、报价过期、Provider 成功/失败/超时、Asset 缺失与重试、积分精确提交/释放。不能运行的测试要写明缺失条件和影响，不得写成通过。

只有获得隔离账号及用户明确的消费上限后，才可进行收费真实任务。验收至少要有一笔图片成功和一笔失败/取消，以及双击/刷新恢复、跨设备历史/下载、跨账户拒绝。记录 quote ID、job ID、Provider ID 和终态、Asset ID、账本 ID、前后余额/冻结额及对象下载结果。用户密码、OTP、支付信息由用户自行输入；没有账号或消费上限时继续安全的离线工作，跳过付费动作。

每项功能只可用以下状态：

- `Unknown`：证据不足或真实行为未观察到。
- `Disabled`：明确关闭，UI 与服务端均不能绕过。
- `Candidate`：本地代码、测试或候选构建通过，尚未完成线上真实交易验收。
- `Verified`：隔离账号在线真实端到端交易完成，且 Provider 终态、归档/历史/下载及正确积分提交或释放均有证据。

图片通过不能推广为视频、音频、Agent 或整个画布通过。视频、音频、Agent 及每项专属图片动作须分别验收后再开放。

### 6. 发布门禁

只读生产检查和本地候选开发可以继续。生产写入、迁移或部署前，先做可审阅的候选、重新核对漂移、准备源码/配置/数据库/对象存储/当前构建的完整备份，验证可恢复并写明回滚步骤；若发布环境、Provider、运行路由、模型白名单、备份或隔离交易证据不满足，就停止依赖发布的步骤，不绕过门禁。没有用户明确授权，不得执行生产写入或部署。未发布必须写“未部署”，未验证必须保留 `Candidate/Unknown/Disabled`。
