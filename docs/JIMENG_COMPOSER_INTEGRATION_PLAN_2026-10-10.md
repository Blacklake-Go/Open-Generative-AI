# 即梦创作输入区研究与 KOYO Studio 融合方案

**研究日期：** 2026-10-10（Asia/Taipei）  
**范围：** 只读浏览即梦国内版、Dreamina 海外版和 KOYO Studio 线上站点；整理交互研究及融合方案。本文是规划文档，不代表已修改、部署或验证任何产品行为。

## 1. 研究结论

即梦输入区的核心不是一个大文本框，而是把「创作类型、模型、参考素材、生成规格、创作技能、价格反馈、提交」组织成同一个上下文明确的创作控制台。选择变化会联动素材槽位、参数可用性和报价；提交前能看到本次生成配置及成本。

KOYO Studio 首页已经有相近的深色玻璃态输入框、Generate/Canvas 切换、图片模型与规格控件、参考图上传、技能快捷项和费用提示。最值得融合的是把当前首页偏图片的 composer，演进为由媒体类型与模型能力驱动的统一入口，并复用 Studio 已有的视频模型及生成链路。建议迁移交互和信息组织，不照搬即梦的配色、品牌装饰或具体价格。

## 2. 浏览器观察记录

观察了以下线上页面及截图对应状态：

- 国内即梦：<https://jimeng.jianying.com/ai-tool/home?type=video>
- 海外 Dreamina：<https://dreamina.capcut.com/>
- KOYO Studio：<https://koyosim.com/>

国内版截图展示视频生成，海外版截图展示图片生成。它们不是同一组规格的中英文翻译，模型、交互和地区策略存在差异。页面会随账号、地区、实验分组及促销变化。

浏览过程中只查看页面、菜单、规格选项和技能目录，没有上传素材、生成内容、确认购买或提交扣费任务。界面上的价格和促销只代表当时页面状态，不应当作稳定定价依据。

### 国内版：视频生成主输入区

- 主区先显示问候标题，再用「生成 / 画布」分段切换创作工作方式。
- 输入框左侧提供参考内容入口；占位说明支持文字和 `@` 引用参考内容，并举例将图片、视频动作、音频音色组合成指令。页面文字提示最多 50 个参考素材。这个上限是当时页面描述，不能不经模型能力校验就写死到 KOYO。
- 底栏把「视频生成」类型、模型、「全能参考」模式、画幅、分辨率、生成数量、时长、`@` 入口、费用及提交按钮放在同一个操作区。
- 模型变更会改变能力说明和可选参数。观察到样片模式和普通模式有不同说明及报价；这说明模式本身会影响任务和价格，不能只换标签。
- 画幅弹层提供多种比例；分辨率弹层显示 480P、720P、1080P；数量可选 1–4。参数变化会刷新估价。
- 时长控件用弹层和步进/预设值控制。技能快捷项以胶囊形式放在输入区下方，带 New/Hot 标识；“更多技能”进入可筛选的技能目录。目录卡片包含作者、热度/使用量、较完整的创作说明及添加操作。
- 技能不只是装饰标签：部分工作流会进入 AI Agent/专门创作流程。融合时应把直接生成参数与 Agent 工作流区分开。

### 海外版：图片生成主输入区

- 截图对应“Create anything you imagine”，Generate/Canvas 切换、参考图入口、图片类型、Seedream 模型、比例、清晰度、张数、`@`、报价和提交操作同处一个宽输入容器中。
- 类型菜单提供图片、视频、音频、数字人等入口；不同类型切换代表不同创作流程，不意味着同一个后端模型可以互换处理。
- 视频参考模式菜单中观察到全能参考、首尾帧、多帧、智能编辑（Beta）和长视频（Beta）等模式。首尾帧模式将输入区改成首帧/尾帧两个槽位，并把画幅切为自动。此为海外版观察，国内版是否提供相同能力需要逐项核实。
- `@` 菜单提示可保存并复用元素；它更像资产库引用，与当前任务临时上传的参考素材是不同来源。
- 点击图片技能会切换到 Agent 创作页面，并载入对应技能说明，表明技能可以是独立流程配置，而非单纯向提示词追加一段文字。

### KOYO Studio 当前线上入口

- 2026-10-10 线上快照中，全站导航分别提供图像、视频、音频和智能体/工作流入口；首页 composer 自身仍是图片生成入口，包含 Generate/Canvas 切换、参考图、提示词、Seedream 图片模型、规格、费用、提交及图片类技能快捷项。参考图按钮当时标示最多 14 张；默认配置显示 1:1、basic、1 张和消耗 15 积分。这些是登录态页面的瞬时配置/显示值，不能当作长期上限或独立报价规则。
- 因此，融合时需要明确“全站媒体导航”与“首页统一 composer 内的媒体类型”是两种不同的信息架构。参考方向是把当前图片 composer 的配置栏扩展为能力驱动的媒体选择和参数区，同时保留不同 Studio 路由需要的独立工作台能力。
- Studio 内已经存在视频工作台、视频模型目录、依模型而变的参数与生成处理，规划应先复用其现有能力边界，不在首页另造一套模型/提供方/计价逻辑。
- 首页快捷技能目前更接近提示词预设；即梦目录中的技能还包含可筛选的策划内容和 Agent 工作流，需要在产品语义和后端执行类型上明确区分。

## 3. 对照与融合方向

| 即梦模式 | 用户价值 | KOYO 已有基础 | 建议融合方式 |
|---|---|---|---|
| 生成 / 画布 | 在创作入口选择直接生成或进入画布 | 首页已有对应切换 | 保留现有顶层切换，不与图片/视频类型混为一个开关 |
| 图片/视频类型 | 明确任务类型 | 图片首页入口、Studio 视频工作台 | 在 composer 操作栏增加类型选择；首期只开放已接通且能力明确的类型 |
| 模型联动规格 | 让用户知道所选模型能做什么 | 图片模型目录、视频模型目录 | 从模型能力派生参数控件、默认值、限制和说明；不维护重复清单 |
| 多模态参考素材 | 上传并在提示词中指代素材 | 现有上传与参考图流程 | 先支持后端明确接受的素材类型；素材标签、限制和校验由模型能力驱动 |
| `@` 引用 | 从本次素材或个人元素中插入引用 | 现有参考图标识/菜单可复用部分交互 | 区分“本次任务参考”和“已保存元素”；无法解析引用时阻止提交并说明原因 |
| 技能胶囊/目录 | 快速启动高质量创作套路 | 首页提示词预设、现有 Agent 路由 | 预设型技能只填表单/提示词；Agent 技能进入独立工作流并展示输入要求 |
| 动态报价与提交 | 配置改变后及时显示本次成本 | 首页费用显示、generation quote API | 报价以服务端为准，提交使用对应有效 quote；报价过期或参数变更时重新获取 |

## 4. 建议目标交互

### 4.1 信息结构

保留首页现有 Generate/Canvas 顶层切换。Generate 模式下将 composer 分为三个清晰层次：

1. **创作内容区：** 多行提示词、参考素材缩略图/命名、上传入口、可用的 `@` 引用提示。
2. **配置操作栏：** 媒体类型、模型、该模型支持的参考模式和规格控件。当前配置无法组合时，立即解释并给出可选值。
3. **提交区：** 服务端报价、必要的质量/样片说明、提交按钮和生成状态反馈。

技能快捷项仍在 composer 下方，控制在当前类型相关的少量推荐项；“全部技能”进入可搜索/筛选目录。小屏时操作项换行或进入规格弹层，不把提交按钮挤出可视区域。

### 4.2 表单状态与能力联动

用一个明确的 composer 状态描述当前草稿，例如：

- `intent`: generate / canvas / agent workflow
- `mediaType`: image / video / audio（仅展示已开放类型）
- `modelId`, `referenceMode`, `workflowId`
- `prompt`, `references[]`（包含素材类型、来源、引用标识和上传状态）
- `aspectRatio`, `resolution`, `duration`, `quantity`, `qualityMode`

模型目录或服务端能力信息决定哪些控件可见、可选值、素材类型及数量限制。切换模型或参考模式时用一次状态更新清理不兼容项，同时保留用户提示词和可重新使用的素材；显示被重置的规格，避免静默改变任务含义。首尾帧等专用模式应由能力配置生成对应槽位，不使用通用上传框假装支持。

### 4.3 报价和提交链路

- 配置发生变化后请求服务端报价；可以做短暂防抖以减少重复请求。界面区分“正在估价”“报价失效”和“无法报价”，不把缺失价格显示为零。
- 报价请求包含模型与会影响成本的全部参数、数量、质量模式及素材/任务模式。展示价格明细或关键计价因子。
- 最终提交引用有效 `quote_id`。服务端重新核对用户、模型、参数、报价有效期和可用额度；报价与草稿不一致时要求刷新报价，不采用客户端自行计算的积分数。
- 复用现有 GenerationJob、路由、Provider、轮询/回调、存储、历史和积分结算流程。成功、失败、超时和重复回调都需要遵循现有幂等扣费/释放/退款规则。
- 页面状态至少覆盖草稿、校验、等待登录、提交中、排队/处理中、成功、失败和可重试。失败时保留提示词与素材，明确说明费用是否扣除或已退回。

### 4.4 技能与 `@`

- 将技能分成**提示词预设**和**执行工作流**两类。预设可插入或组合文本；工作流有自己的必填输入、任务路由和结果状态，不伪装成普通模型选项。
- 技能目录展示适用类型、需要的输入、会修改的配置以及由谁提供；添加前能预览并移除。
- `@` 首期仅提供当前任务已上传素材的引用。已保存元素库可作为后续阶段，届时要补充权限、删除、过期和跨任务可见范围规则。
- 引用以结构化引用 ID/索引传入服务端，不依赖提示词中偶然匹配到的“@图片1”文本。

## 5. 分阶段落地

### 阶段 0：能力和业务链路盘点

逐项核实当前生产及代码中的图片/视频模型目录、模型能力、上传格式与限制、服务端报价、生成提交、Provider 参数映射、任务终态、对象存储、历史列表和积分结算。检查首页与 VideoStudio 的状态/参数映射，列出真实支持的媒体和参考模式。生产状态与本地 checkout 必须分别记录；上线前以当时线上证据重新校验。

### 阶段 1：融合图片与视频入口

沿用现有首页图片体验，将类型选择与 Studio 视频目录和参数规则接通。只开放“报价、真实路由、终态结果、历史和扣费/退款”全部可验证的模型。图片继续复用当前首页路径，视频尽可能复用 VideoStudio 逻辑，不从 UI 组件复制一套业务控制器。

### 阶段 2：参考模式和 `@`

先完成已支持素材的缩略图、引用、移除、上传失败、格式/数量校验及提示词中的结构化引用；然后按确切模型能力增加视频/音频参考模式或帧槽位。保存元素库作为独立需求处理。

### 阶段 3：技能体验

整理现有技能，标记适用媒体类型及执行类别。首页挑选与当前类型匹配的精选项；目录支持搜索与分类。只将已接通工作流展示为 Agent 技能，其余明确标为提示词预设或不可用。

### 阶段 4：端到端验收与发布

在隔离测试用户和明确额度上限下，以真实链路验收登录、报价、提交、Provider 终态、产物可见/可下载、历史记录及成功扣费；失败路径检查幂等释放或退款。按项目发布流程准备备份、发布范围和回滚点，再决定是否上线。

## 6. 验收标准

- **视觉：** 明确显示当前创作类型、模型、参考模式和生成规格；操作区在桌面与窄屏均可用，层级与当前 KOYO Studio 协调。
- **交互：** 每项规格变化都即时校验兼容性并刷新服务端报价；上传、引用、模式切换、取消、失败重试均有明确状态；菜单支持键盘操作，弹层和提交区不吞点击。
- **计费：** 显示值来自服务端报价，提交以有效 quote 为准；无法报价时不允许用户误以为免费；扣费、释放或退款与任务终态一致。
- **生成证据：** 至少一条图片和一条视频真实任务走通认证、Provider 终态、结果存储、历史/下载和积分结算。页面加载、模型列表、健康探测、模拟数据或旧任务不能替代该证据。
- **技能：** 清楚区分预设和 Agent 工作流，任务输入能到达对应后端流程。
- **无障碍与品牌：** 使用站点 `app/globals.css :root` 的 token 和现有共享组件；遵循深色玻璃态与 KOYO 品牌，不复制即梦白青渐变作为第二套品牌。满足键盘焦点、对比度和减少动态效果偏好。

## 7. 实施前置和边界

本次只完成浏览器研究与方案，没有修改 UI、提交生成、付费或部署。当前工作区已有大量未提交改动，后续实施应先审查相关文件的现有差异，并在受控备份/发布流程内限定修改范围，不应通过重置或清理工作区来开始。

实际 UI 实施前，按项目要求重新阅读并遵循 `docs/UI_DESIGN_SYSTEM.md` 与 `docs/UI_REPAIR_INSTRUCTION.md`。具体实现优先检查并复用 `components/home/HomeStudioPromptComposer.jsx`、`components/home/JimengHomePortal.jsx`、`packages/studio/src/components/prompt/PromptComposer.jsx`、`packages/studio/src/components/VideoStudio.jsx`、`app/api/generation/quote/route.js` 和 `lib/services/generationQuote.js`；这些路径是盘点入口，不代表其当前代码已通过生产验收。
